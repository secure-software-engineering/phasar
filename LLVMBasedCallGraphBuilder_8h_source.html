24/// Constructs a call-graph using the given CGResolver to resolve indirect
25/// calls.
26///
27/// This overload does not mutate the IRDB. Use
28/// buildLLVMBasedCallGraphWithExternCallbackModels() if PhASAR should insert
29/// its model functions first.
30///
31/// Uses a fixpoint iteration, if
32/// `CGResolver.mutatesHelperAnalysisInformation()` returns true and the
33/// soundness S is not Soundness::Unsound.
34///
35/// \param IRDB The IR code where the call-graph should be based on
36/// \param CGResolver The resolver to use for resolving indirect calls.
37/// \param EntryPoints The functions, where the call-graph construction should
38/// start. The resulting call-graph will only contain functions that are
39/// (transitively) reachable from the entry-points.
40/// \param S The soundness level. May be used to trade soundness for
41/// performance.
42[[nodiscard]] LLVMBasedCallGraph
43buildLLVMBasedCallGraph(const LLVMProjectIRDB &IRDB, Resolver &CGResolver,
44 llvm::ArrayRef<const llvm::Function *> EntryPoints,
45 Soundness S = Soundness::Soundy);
